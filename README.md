# Philips PM2525 multimeter firmware: decompilation and rebuildable source

A complete decompilation of the firmware of the Philips PM2525 digital multimeter: PM2525/3, software
version **S25**, Intel 8031 CPU, 32 KB 27C256 EPROM, battery-backed 6116 RAM. You can read it, change it
and build it back into an EPROM image.

- **Every routine is named and documented.** That is 492 functions, covering measurement and ranging,
  calibration, the remote command parser, the option-board (GPIB/RS232) link, the display and the
  keyboard.
- **Readable C for every subsystem.** [`src/`](src/README.md) has the generated C, and
  [`src/clean/`](src/clean) has hand-cleaned C. The clean C is checked against the original code
  running in an emulator: 4393 cases with no difference, and 721 out of 721 remote command lines.
- **Buildable source.** [`fw/`](fw/README.md) is a relocatable assembler source for SDCC that rebuilds
  the factory image **byte for byte**. You can edit it, and you can link C routines into it.
- **Notes.** [`DECOMPILATION.md`](DECOMPILATION.md) has the findings: hardware map, calibration
  storage and recipes, the remote command set, and the differences from the older S08.
  [`CALIBRATION_BACKUP.md`](CALIBRATION_BACKUP.md) explains how to back up a meter's calibration
  through the option bus.

## Branches

| Branch | Firmware it builds |
|---|---|
| `main` | **Unmodified.** `fw/pm2525.asm` builds an image identical to the factory S25 EPROM. |
| `optimized` | **Smaller, same behaviour.** Long jumps and calls are shortened wherever they reach, which frees 915 bytes of ROM (931 free instead of 40). It also shows how to link a routine written in C. Passes the same test suite. |

Start new modifications from `optimized` if you need ROM space, or from `main` if you want to stay
as close to the factory firmware as possible.

## Step-by-step guide

The steps are for Windows and PowerShell. Python and SDCC also run on Linux and macOS (set `SDCC_BIN`
to the folder with `sdas8051`). The Ghidra script in Part 2 is Windows-only.

### Part 1: set up (once)

1. **Install the tools:**
   - [Git](https://git-scm.com/download/win).
   - [Python 3.8 or newer](https://www.python.org/downloads/). Tick *Add python.exe to PATH* in the
     installer.
   - **SDCC 4.5**, the 8051 C compiler, assembler and linker:
     ```powershell
     winget install SDCC.SDCC
     ```
     It installs to `C:\Program Files\SDCC`. If you put it elsewhere, set
     `$env:SDCC_BIN = "D:\path\to\SDCC\bin"`.
2. **Get the source:**
   ```powershell
   git clone https://github.com/criscrafter/Philips-PM2525-Decompilation.git
   cd Philips-PM2525-Decompilation
   ```
3. **Pick a branch:**
   - `git switch main`: the unmodified firmware.
   - `git switch optimized`: 915 bytes free for your own code.
4. **Check that everything works:**
   ```powershell
   python tools/test_fw.py
   ```
   It must end with `ALL TESTS PASSED`. On `main` it also prints `IDENTICAL to ...`: the source
   rebuilds the factory EPROM byte for byte. The build is in `fw/out/pm2525.bin`.

You don't need an EPROM dump for any of this; the tools rebuild the original image from the source.
If you have your own dump, save it as `firmware/PM2525_S25.BIN` and the tools compare against it.

### Part 2: decompile to raw C (optional, the result is already here)

The decompiled C is already in the repository:

| Where | What |
|---|---|
| `src/*.c` | **Raw C** generated by Ghidra, split into one file per subsystem, with names and comments |
| `src/clean/*.c` | the same, rewritten by hand into readable C (not regenerated) |
| `fw/pm2525.asm` | the full annotated assembly, which is what gets compiled |

To produce the raw C yourself, for example after adding names, do this:

1. **Install Ghidra and a JDK.** Unzip both; no installer is needed:
   - [Ghidra 12.x](https://github.com/NationalSecurityAgency/ghidra/releases);
   - a JDK 21 or newer, e.g. [Temurin](https://adoptium.net/).
2. **Tell the script where they are**, in the same PowerShell window:
   ```powershell
   $env:GHIDRA_HOME = "C:\tools\ghidra_12.2_PUBLIC"
   $env:JAVA_HOME   = "C:\tools\jdk-25.0.5.1+2"
   ```
3. **Optional inputs:**
   - your own EPROM dump as `firmware/PM2525_S25.BIN` (otherwise the image rebuilt from source is
     used);
   - the S08 image as `firmware/reference_S08/PM2525_S08_ko4bb.BIN` for the S08/S25 comparison.
4. **Run the decompiler.** It takes a few minutes:
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\run_all.ps1
   ```
5. **Results:**
   - `out/PM2525_S25_ghidra.c`: all 495 functions in one file;
   - `out/PM2525_S25.asm`: the annotated disassembly;
   - `out/*.md`: the range, calibration and analog tables;
   - `src/*.c`: the raw C split by subsystem.
6. **To rename something,** edit `tools/s25.sym` and run step 4 again. Each line is
   `code|data|bit|xdata ADDRESS name # comment`.

If Ghidra fails with *"data file must be inside the data dir"* (an OSGi/Felix error), add this line to
`support\launch.properties` in the Ghidra folder:
`VMARGS=-Dapplication.settingsdir=C:/Users/<you>/ghidra_settings`

### Part 3: modify and recompile

**Important:** the C in `src/` is for reading and understanding. It is **not** a buildable program.
Ghidra's C is not exact, and compiled C would not fit: the 32 KB EPROM is full. What gets compiled is
`fw/pm2525.asm`, plus any C routines you add in `fw/c/`. All routines in it are named like in the C,
and every address is symbolic, so you can insert, delete and rewrite code freely. The linker moves
everything else. The rules are in [`fw/README.md`](fw/README.md).

**Example A: change something in assembly.** This changes the version shown in the CHECK menu
from S25 to S26:

1. Open `fw/pm2525.asm` and search for `T_59AF`:
   ```
   T_59AF::
           .db 0x32, 0x35          ; 59AF 25
   ```
2. Change `0x35` ("5") to `0x36` ("6").
3. Rebuild and test:
   ```powershell
   python tools/test_fw.py
   ```
   The output now reports `differs from ... in 1 bytes`. The tests still pass.
4. Your new firmware is `fw/out/pm2525.bin`.

**Example B: rewrite a routine in C.** The `optimized` branch does this with `func_to_cmd_index`.
To do the same with another routine:

1. Find the routine in `src/clean/*.c` (readable logic) and in `fw/pm2525.asm` (the label `name::`).
2. Write `fw/c/name.c`:
   ```c
   #include "pm2525_fw.h"          /* all firmware variables, SFRs and bits by name */
   unsigned char c_name(void) { ... }
   ```
   C may only use `__xdata` variables, because internal RAM is full. Don't use initialised globals
   either: no startup code runs for C.
3. In `fw/pm2525.asm`, delete the assembly body of `name::`. Put a few lines of glue at the end of
   `CODE_B` that keep the original interface: same registers in and out, and register bank 0 for
   the C code. Copy the glue of `func_to_cmd_index` on `optimized`. To see which registers your C
   code changes, look in `fw/out/name.lst`.
4. Run `python tools/test_fw.py`. The build tells you if the code doesn't fit, or if C uses internal
   RAM.
5. If the routine has behaviour the tests don't cover yet, add a case to `tools/check_clean.py`.
   It runs the original routine in an emulator and compares.

**More space:** set `shrink = yes` in `fw/build.ini` (already set on `optimized`). It frees about
900 bytes without changing behaviour or timing.

**What the tests don't check:** timing and the hardware (ADC, display, motor switch, I²C devices).
Keep away from the timing-critical code listed in `fw/README.md`, or test on a meter.

### Part 4: put it in the meter

1. Burn `fw/out/pm2525.bin` into a **spare** 27C256 (32 KB) EPROM with an EPROM programmer, for
   example an XGecu T48 or TL866.
2. Switch the meter off and unplug it. Swap the EPROM and **keep the original**. Mind pin 1 and the
   notch.
3. The calibration lives in the battery-backed RAM, not the EPROM, so swapping EPROMs keeps it. If
   anything looks wrong, put the original EPROM back.

## Not included

These files are not in the repository:
- **The factory EPROM images.** The tools use your own dump at `firmware/PM2525_S25.BIN` if present.
  Without it, they rebuild the original image from `fw/reference/pm2525_original.asm` (MD5
  `a2f9121a0083f12b186cc1258656c072`). The S08 reference image (`firmware/reference_S08/`) is
  available from the KO4BB manual archive.
- **The Philips manuals** (service and operator manuals, service notes). The notes refer to them as
  `manuals/01_…` to `manuals/05_…`. Only my own research notes (`manuals/03`, `06`, `07`) are included.
- **Meter RAM dumps.** The calibration tests use an empty RAM unless you put a dump in `backup/` or
  point `PM_RAM` at one.
- **Ghidra project and generated listings** (`out/`). `tools/run_all.ps1` regenerates them with
  Ghidra 12.2 headless (it needs the EPROM dump).
